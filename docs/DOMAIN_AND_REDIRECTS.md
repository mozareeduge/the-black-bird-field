## UNHAPPY Scenario subdomain

`unhappy.theblackbirdfield.com` is final (D-UNHAPPY-DOMAIN); no
alternative subdomain name is open for consideration.

Target configuration:

- GitHub Pages custom domain on `mozareeduge/UNHAPPY-scenario`: `unhappy.theblackbirdfield.com`, HTTPS enforced after certificate issuance.
- Cloudflare DNS: `CNAME unhappy → mozareeduge.github.io`, **DNS-only** (not proxied) during verification and certificate provisioning. Do not proxy it afterward without a documented production reason, and never create a wildcard record.
- The approved release's `index.html` (blob sha1 `fb67ebce1bcce965e4f91f4e8e2e0e36d910abae`) is never edited or proxy-rewritten to add canonical metadata (D-UNHAPPY-CANONICAL-RESOLUTION) — the custom HTTPS domain becomes canonical through GitHub Pages configuration and portfolio-side references alone.

This configuration is applied only through `scripts/release_actions/unhappy_domain_action.py`, gated by a separate, explicit authorization naming the repository, domain, Cloudflare zone, record target, and proxy state (`A-CONFIGURE-UNHAPPY-DOMAIN` in `docs/authority/PROJECT_ACTION_CONFIG.json` / the contract's `operations/ACTIONS.json`). It is not authorized by implementation work alone.

Validation performed by that action's `readback` mode: DNS resolves,
GitHub Pages reports the domain verified, the HTTPS certificate is valid,
HTTP redirects to HTTPS, the live response ends at
`https://unhappy.theblackbirdfield.com/` with no conflicting canonical
element, the source blob is unchanged, and zero third-party runtime
requests are observed.

## Redirects

- `www.theblackbirdfield.com` → apex: existing Cloudflare redirect rule, kept as-is.
- Historical flat-file routes (`/about.html`, `/works.html`, `/unhappy-scenario.html`, etc.) are generated static redirect stubs (`meta refresh` + `location.replace()`), not Cloudflare rules — see `docs/DEPLOYMENT.md` § Routes.
- Root-level work aliases (`/the-black-bird/`, `/winter-road/`, `/unhappy-scenario/`, `/grave-machine/`, `/taroke-remixer/`) are full rendered pages generated by the build, not redirects of any kind. No Cloudflare rule is needed or used for them.

Any new Cloudflare rule beyond the two above must be for an explicitly
retired external hostname, must preserve path and query where applicable,
and must be recorded here when added.
